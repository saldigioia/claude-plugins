# Scaffold System

Generate a fresh Every Layout system into a project that has none yet. This is the greenfield counterpart to `/plan-migration` — that skill scans an *existing* codebase and proposes a phased adoption plan; this skill creates the four foundational files a brand-new project needs on day one, with nothing to migrate away from.

$ARGUMENTS

Parse `$ARGUMENTS` as `<target styles dir> [brand name]`. If the target dir is omitted, default to `src/styles`. If the brand name is omitted, use `Brand` as the placeholder and leave the values clearly marked for editing.

## Process

### 0. Refuse to overwrite

Before writing anything, check whether `<target>/tokens.css`, `<target>/layers.css`, `<target>/primitives.css`, or `<target>/global.css` already exist (Glob the target dir). If **any** of the four already exists:

- Stop. Do not write, do not overwrite, do not merge.
- Report which file(s) exist.
- Point the user to `/plan-migration <target>` instead — that skill is built for a codebase that already has CSS to reconcile, not a clean slate.

This skill only ever creates a system where none exists. It is not an upgrade path.

### 1. Emit the four target-dir files

Create `<target>/` (via `mkdir -p` if needed) and write the four files below **exactly as specified** — these are canonical templates, not sketches. They are gate-clean against `bin/css-strict.sh` on arrival: every spacing value comes from the modular scale (ELA_004), every property is logical (ELA_002), no arbitrary numbers, no `!important` outside the reduced-motion reset (ELA_003).

#### `tokens.css`

Tier 1 (global, invariant scale — frozen API per `skills/css-design-system/references/token-rules.md`) plus Tier 2 (the 9 mandatory brand tokens). Copy this verbatim, replacing only the bracketed brand placeholder values:

```css
/**
 * Design Tokens — Tier 1 (global) + Tier 2 (brand)
 * Generated by /scaffold-system. See skills/css-design-system/SKILL.md for
 * the three-tier token architecture and skills/css-layout-engine/SKILL.md
 * for the modular scale this file defines.
 */

:root {
  color-scheme: light dark;

  /* ============================================
     TIER 1 — GLOBAL (invariant, frozen API)
     Modular scale — ratio 1.5 (perfect fifth)
     Do not rename. Do not add off-scale values.
     ============================================ */
  --ratio: 1.5;
  /* Derived via calc chains, never hardcoded: change --ratio or --s0 at
     :root and the whole scale recomputes (a subtree override requires
     re-declaring the chain there — see token-rules.md, Calc Chain Rule). */
  --s-5: calc(var(--s-4) / var(--ratio)); /* = 0.132rem */
  --s-4: calc(var(--s-3) / var(--ratio)); /* = 0.198rem */
  --s-3: calc(var(--s-2) / var(--ratio)); /* = 0.296rem */
  --s-2: calc(var(--s-1) / var(--ratio)); /* = 0.444rem */
  --s-1: calc(var(--s0) / var(--ratio));  /* = 0.667rem */
  --s0: 1rem;
  --s1: calc(var(--s0) * var(--ratio));   /* = 1.5rem */
  --s2: calc(var(--s1) * var(--ratio));   /* = 2.25rem */
  --s3: calc(var(--s2) * var(--ratio));   /* = 3.375rem */
  --s4: calc(var(--s3) * var(--ratio));   /* = 5.063rem */
  --s5: calc(var(--s4) * var(--ratio));   /* = 7.594rem */

  --measure: 65ch;
  --border-thin: 1px;

  /* ============================================
     TIER 2 — BRAND (overridable per skills/css-design-system
     references/token-rules.md; the 9 tokens below are the
     mandatory brand interface — every brand file MUST define
     all 9, no partial brand files)
     ============================================ */

  /* --- [BRAND_NAME] brand values — edit this block only --- */
  --br-color-surface: light-dark(#ffffff, #1a1a1a);
  --br-color-surface-raised: light-dark(#f8f8f8, #242424);
  --br-color-text: light-dark(#212121, #e0e0e0);
  --br-color-text-muted: light-dark(#666666, #999999);
  --br-color-accent: light-dark(#7a2e1f, #d97757);
  --br-color-interactive: light-dark(#1a56db, #6c9ef8);
  --br-color-focus: light-dark(#1a56db, #6c9ef8);

  --br-font-body: Georgia, "Times New Roman", serif;
  --br-font-heading: Georgia, "Times New Roman", serif;
  /* --- end brand block --- */
}
```

Notes to give the user inline (as a comment or in the report, not as extra tokens): the 9 required tokens are `--br-color-surface`, `--br-color-surface-raised`, `--br-color-text`, `--br-color-text-muted`, `--br-color-accent`, `--br-color-interactive`, `--br-color-focus`, `--br-font-body`, `--br-font-heading` — this is the complete mandatory set, no more, no fewer. Do not invent a 10th brand token or promote something to Tier 1 that is actually a brand decision (ELA_004, ELP_005).

#### `layers.css`

Copy this exactly — the layer order is contractual (`skills/css-design-system/references/layer-rules.md`), not a suggestion:

```css
@layer global, brand, components, bespoke.legacy, bespoke.dataviz, bespoke.editorial, bespoke.embed;
```

Nothing else goes in this file. Consumer CSS stays unlayered by design (highest priority).

#### `primitives.css`

Do **not** restate the 13 primitives' ~400 lines by hand inside this skill — that invites drift between the skill body and the real build artifact. Instead, copy the canonical file verbatim:

```!
cp "${CLAUDE_PLUGIN_ROOT}/demos/every-layout.css" "<target>/primitives.css"
```

Cite the source in the copied file's header comment (it already carries one — leave it intact) so a future reader can find the origin. If `<target>/primitives.css` needs project-specific additions later, they belong in `components.css` or a bespoke layer file, never inline edits to this copy — that is what makes future `cp` re-syncs from the plugin safe.

#### `global.css`

A minimal skeleton — imports, body defaults from the brand tokens, and the two non-negotiable accessibility patterns (ELP_028, ELP_029) plus a skip link. Write:

```css
/**
 * Global styles — imports order matters: layers.css MUST load first so the
 * @layer statement registers the cascade order before any layered rule
 * anywhere else in the project is parsed.
 */
@import url("layers.css");
@import url("tokens.css");
@import url("primitives.css");

*,
*::before,
*::after {
  box-sizing: border-box; /* ELP_003 — universal border-box */
}

body {
  margin: 0;
  font-family: var(--br-font-body);
  color: var(--br-color-text);
  background-color: var(--br-color-surface);
}

h1, h2, h3, h4, h5, h6 {
  font-family: var(--br-font-heading);
}

/* Skip link — required on every page (skills/css-design-system/references/accessibility.md) */
.skip-link {
  position: absolute;
  inset-block-start: 0;
  inset-inline-start: 0;
  padding: var(--s-1);
  background: var(--br-color-surface-raised);
  color: var(--br-color-text);
  transform: translateY(-100%);
  z-index: 60; /* --z-skip */
}

.skip-link:focus {
  transform: translateY(0);
}

/* Focus visibility — ELP_029, WCAG 2.4.7 / 2.4.11 */
:focus-visible {
  outline: 3px solid var(--br-color-focus);
  outline-offset: 2px;
}

:focus:not(:focus-visible) {
  outline: none;
}

/* Motion safety — ELP_028, WCAG 2.3.3 */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Use `@import url(...)` only for these first-party same-directory files at the top of `global.css` — this is the project's own entry point, not a rule against `@import` inside the compiled system; `skills/css-design-system/references/performance-rules.md` prohibits `@import` *within* the shipped stylesheet bundle, so if the build pipeline concatenates these four files into one output, replace the imports with `<link>` tags in HTML instead and drop them from this file. State which approach was used in the final report.

### 2. Escape hatch registry

If `escapes.md` does not already exist at the **project root** (not the target styles dir):

```!
cp "${CLAUDE_PLUGIN_ROOT}/escapes.md.template" "escapes.md"
```

If it already exists, leave it untouched and note that in the report — this skill never overwrites an existing escapes registry.

### 3. Offer the pre-commit gate (ask, don't auto-run)

Ask the user whether they want the axiom gate wired into `git commit`. Do not run this without an explicit yes:

```
bash ${CLAUDE_PLUGIN_ROOT}/bin/install-git-hooks.sh
```

Explain what it does before asking: it installs a `pre-commit` hook that runs `bin/css-strict.sh` (and `bin/js-budget.sh` if a dist dir exists) on every commit, blocking commits that violate the axioms unless suppressed via `escapes.md`. If they decline, mention `/strict-check` as the on-demand equivalent.

### 4. Verify and report — no destructive steps

Run nothing that mutates state beyond the file creation and copies above. The final step is a report, not a command. Print:

- Which of the 4 files were created (all 4, on a clean scaffold) and their paths.
- Whether `escapes.md` was created or already existed.
- Whether the pre-commit hook was installed (or declined/skipped).
- Next actions: run `/strict-check <target>` to confirm the gate passes, and `/audit-layout` once real markup exists to score it against the 24-point rubric.
- The performance budget the new system must stay under: **34 KB minified / 8.5 KB gzipped** CSS; **15 KB per-route / 30 KB page-total** JavaScript (both from `skills/css-design-system/references/performance-rules.md`).

## Constraints

- MUST refuse and defer to `/plan-migration` if any of the four target files already exists — never overwrite.
- MUST cite `ELC_*` / `ELP_*` / `ELA_*` IDs when explaining any choice made during scaffolding.
- MUST NOT invent tokens outside the documented tiers (Tier 1 `--gl-*`-class invariants — expressed here via the frozen bare names `--ratio`, `--s-5`..`--s5`, `--measure`, `--border-thin` per the Frozen API in `references/token-rules.md` — Tier 2 `--br-*`, Tier 3 unprefixed component instance).
- MUST emit exactly the 9 mandatory `--br-*` tokens in Tier 2 — no more, no fewer — using `light-dark()`.
- MUST NOT modify any existing file — this skill only creates files that do not yet exist.
- Every emitted spacing/scale value MUST come from the modular scale (ELA_004) — no arbitrary numbers.
- The layer order in `layers.css` is contractual — copy it exactly, do not reorder or add top-level layers.
- MUST copy `primitives.css` from `demos/every-layout.css` rather than paraphrasing it inline.
- MUST ask before running `install-git-hooks.sh` — never install the pre-commit hook silently.
- MUST NOT run any destructive command (no force-overwrite flags, no `rm`).
